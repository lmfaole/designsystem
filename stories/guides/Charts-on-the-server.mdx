# Charts on the server

Our pages are rendered on the server (guide **Server rendering**), and a chart is the part of a page most likely to jump or to disagree between the server and the browser. What the chart library does, and what we do about it.

## 1. What is in the server HTML

TanStack Charts renders the real SVG on the server, at an initial width (640 px by default), together with the table. The server cannot measure the container, so the chart is laid out again after the page loads (it measures its container and relayouts), and text
is measured with estimates that the browser corrects once fonts have loaded. A small relayout is expected. The library has no placeholder-only server mode.

## 2. Reserve the height

`ChartFrame` gives its box its final height from the first paint, in CSS: between the height you ask for and 480 px, a fifth of the box's own width (`clamp(height, 22cqw, 480px)`, with `cqw` a percent of the container's width). Before 8.12 the height was worked out in script after the
chart had measured itself, so a wide chart grew from 180 to 220 px or more after the page loaded, and everything below it moved; a chart that loads as an island (`client:visible`) made it later still. A chart whose height is its rows (`RankedBarChart`) has a fixed height.
Never collapse a reserved place when there is nothing to show (web.dev: reserve space, a good layout shift is 0.1 or less at the 75th percentile): an empty chart is `ChartEmpty` at the same height.

## 3. The same on both sides

- Formatters are named: `nb-NO`, and `Europe/Oslo` for a time. A bare `toLocaleString()` gave «12,345» in an English browser and «12 345» in a Norwegian one, and a tooltip that disagreed with the table. `formatChartValue` is the one place, and a test fails on a bare `toLocaleString()` or an `Intl` formatter without a locale.
- A definition is made from the data and constants, never from the clock, the window or the locale of the runtime; sort the data before you pass it.
- A minus is U+2212 and the grouping is a non-breaking space: `nb-NO` gives «−12 345,6».

## 4. States

| State | Do |
| --- | --- |
| Loading | `StreamedSection` with a `SectionSkeleton` at the chart's height |
| Empty | The chart says why, at its height: «Ingen data i denne perioden.» (`emptyMessage`) |
| Error | `ErrorMessage` in the part that failed; never an empty chart |
| Stale | A `Freshness` line under the title; the chart stays |
| One point, zeros | A dot is drawn for one point; all zeros give a flat chart, and the `summary` says so; a donut with only zero or negative values is empty |

## 5. Phones

Fewer labels (`labelEvery`), horizontal bars for long labels (`RankedBarChart`), a table instead of a chart for more than about a hundred points. A few thousand cells is what the library recommends for SVG; canvas only helps when node creation is the measured bottleneck, and it paints only after the page loads.

## 6. Weight

`ChartFrame` is the one client file of the charts, and brings the chart library with it; the donut and the sparkline are plain markup with no script, so prefer them where they do the job. A chart far down a page is an island that loads when it is seen (`client:visible`),
which is why its place is reserved.
