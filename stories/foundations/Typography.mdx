# Typography

Few sizes, few weights, three levels, and one measure. A page never sets a size, a weight or a colour: it asks `Text` and `Heading`. The
rules are from GOV.UK, Primer, Atlassian, NAV Aksel, Carbon, Butterick's *Practical Typography* and WCAG, put into our terms; each source is at the end.

## 1. What we have

| | Values |
| --- | --- |
| `Text` size | `xs`, `sm`, `base` (the default), `lg` |
| `Text` tone | `default`, `muted`, `destructive` |
| `Text` weight | `normal`, `medium`, `semibold` |
| `Heading` look | `page`, `section`, `label`, `item` |
| Typefaces | Geist for the interface, JetBrains Mono for headings and code (see **Tokens / Overview**) |

`Heading` takes a `level` (the element, which makes the page's outline) and a `look` (how it looks), chosen apart: a section is an `h2` whatever it looks like, and a
title is never made by making text bold or larger (Atlassian, Aksel).

  <Heading level={3}>Liten seksjonstittel</Heading>

## 2. Few sizes

The established systems have six to eight sizes in all (GOV.UK seven, Primer six, Atlassian a 4 px grid from 12 to 32 px), and Butterick asks for no more than three heading
levels, two if possible, with the smallest visible step between them. We have four text sizes and two page-title sizes, and use them for three levels:

1. **The page** (`PageHeader`): one `h1`.
2. **A section** (`PageSection`, `SectionGroup`): its title as a small uppercase label or a semibold heading, an `h2`, and its parts one level down (`h3`).
3. **An item** (a row's name): `item` or the strong name in `Rows`.

There is **no fourth level of emphasis**. Bold is for what stops something or what is the point (GOV.UK: «use bold text sparingly»). Italic is not used, and never together with bold (Butterick).

## 3. Reading width and line height

- A line of running text has **45–90 characters** (Butterick); GOV.UK says no more than 75. The reading column is 48 rem, which is wider than that for a paragraph, so **a
  paragraph stands in `Stack width="prose"`** (about 65 characters). A list, a row or a table can use the whole column.
- Line height is the pair that comes with each size and is about one and a half for body text, inside Butterick's 120–145 % of the type size and a little above it. Do not set one yourself.
- Text must still work when the reader sets it larger or looser: WCAG 1.4.12 asks that nothing is cut off when the line height is 1.5 times the size, paragraph spacing twice, letter spacing 0.12 em and word
  spacing 0.16 em; WCAG 1.4.4 asks that text can be resized to 200 %. So size text in relative units and never in viewport units (WCAG failure F94), and let boxes grow with their text.

## 4. Emphasis

- **Weight first, then tone.** A name is `medium`, the rest is `muted` and small. That is how a row is scanned down its left edge.
- **Uppercase is for short labels** (`Heading look="label"`), with letter spacing; Butterick asks for 5–12 % extra, and the label look has 10 %. Never a sentence in capitals.
- **A heading is not centred, not underlined**, and is kept together by `text-balance` for the page title.
- `destructive` text is for what stops something, with a symbol and words.

## 5. Figures and code

- Figures that line up (a column, a counter, a clock) use tabular numbers: `Text numeric` (GOV.UK: tabular numbers for comparison, for reference numbers and for counters that update).
- Identifiers, paths, commands and ids are monospace: `Code`. Inline code is 0.9 em of its sentence, in monospace.

## 6. Norwegian

- Quotes are « » and not " ". A range is an en dash without spaces («9–15», «2020–2025»), or «fra … til» in a sentence; a spaced hyphen is not used (Aksel, *Skriveregler*).
- A number and its unit or `%` stay together with a non-breaking space («93 %», «12 m/s»); thousands are grouped with a space (`Intl` does both in nb-NO). A minus is −.
- `<html lang="nb">` is set once on the page: screen readers read in the right language and the browser knows which language to hyphenate. Do not rely on hyphenation:
  `hyphens: auto` needs the language's dictionary in the browser (MDN), and we have not checked every browser for Norwegian.

## 7. Check it

1. Read the page at 200 % zoom and at 400 px wide: nothing is cut, nothing scrolls sideways.
2. Count the levels: page, section, item. If you need a fourth, the structure is wrong, not the type.
3. Cover everything but the left edge: is the name of each row the strongest part?
4. Look at the longest paragraph: is it in `width="prose"`?
