# Icons: use them

## Before you reach for one

An icon is not free. Few icons are understood by everyone (home, search, print), the same icon means different things to different people (a heart is love or «save»), and a feature behind an icon nobody recognised goes unused
(NN/G, *Icon usability*; GOV.UK avoids icons for the same reason). So:

1. **Ask whether the page needs it.** If the word says it, the icon only adds noise. Icons earn their place where a page is scanned again and again: the kind of a row, a status, a section that must be found.
2. **Use a meaning that exists** before you ask for a new one (Atlassian), and **one meaning for one icon**: a magnifier only ever means search.
3. **Put the word beside it.** A label that is always visible, never only on hover. An icon alone must be unmistakable and has a `label`.


**Use an icon wherever it makes something quicker to find or to understand.** A page of words is slow to scan; a page
where the kind of a thing, its status and its actions are also drawn is read at a glance. The design system makes this the
easy way: icons are a meaning you ask for (`<Icon name="failure" />`), the components that show titles, rows, statuses and
errors take one, and a status with a symbol never depends on its colour.

## Where to use them

- **A section's title**: `icon` on `PageSection`, `SectionGroup`, `SubSection`. The page is found by its shapes before it is read.
- **The kind of a row**: `Rows` with `lead="icon"`, `icon` and `iconLabel` per row. A pull request, an issue and a discussion in one list tell themselves apart.
- **A status**: `StatusLine`, an `icon` per item. `Tester feilet` with a cross is seen; the colour is a second signal, never the only one.
- **An action**: `<Icon name="refresh" slot="start" />` in a `Button`. The verb is recognised without reading it.
- **A page to go to**: `icon` on `NavBar` and `SubPages`. The same place always has the same symbol.
- **An error**: `ErrorMessage` has one already. An error is told from a message at once.

## Where not

- **Decoration.** An icon that means nothing is noise. If you cannot say what it means, leave it out.
- **The same icon on every row.** Twenty pull requests with the same pull-request icon say nothing; use the icon to tell
  *kinds* and *states* apart (a draft, an open one, a merged one), not to repeat the list's title.
- **An icon in place of a word** where the word is short and the icon is ambiguous. An icon next to its word is the point;
  an icon alone must be unmistakable and have a label.
- **A new colour.** An icon takes the text's colour, or `muted`, `destructive`, `primary`. There is no green: a status that
  is good is plain, one that stops something is `destructive`.

## Meanings, not glyphs

Icons are named for what they **mean**: `merge`, not `git-merge`; `waiting`, not `hourglass`. A page asks for a meaning,
so two pages that mean the same thing show the same symbol, and changing the glyph for a meaning is one line in
`src/lib/icons.ts`. See the **Catalogue** for every meaning.

## The groups

The catalogue has 70 meanings in seven groups. A group is a place to look first, not a rule about where to use an icon.

| Group | For |
| --- | --- |
| The work | Code, reviews, tickets and conversations: `pull-request`, `issue`, `discussion`, `merge`, `tasks` |
| How it stands | The state of a thing: `success`, `failure`, `warning`, `info`, `pending`, `waiting`, `blocked` |
| People and time | Who and when: `person`, `people`, `view`, `time`, `history`, `calendar`, `notification`, `mail` |
| Place and weather | Where it is and what the sky does: `place`, `weather`, `rain`, `wind`, `temperature` |
| Getting around | On foot and by public transport: `walk`, `bus`, `tram`, `metro` |
| What you can do | Actions: `refresh`, `search`, `filter`, `sort`, `copy`, `add`, `edit`, `delete`, `link`, `external`, `close`, `settings` |
| Direction | Where to go: `back`, `chevron-down`, `chevron-right` |

## Choosing between close meanings

These are our conventions, so that two pages that mean the same show the same symbol.

| Meaning | Use it for | Not for |
| --- | --- | --- |
| `success` | A result that is good and has been checked: tests passed, approved | A button that confirms (`done`) |
| `done` | The act of confirming or a tick in a choice | A state of a thing (`success`) |
| `failure` | Something that ran and failed: tests, a build | A thing that is held up (`blocked`) or in doubt (`warning`) |
| `blocked` | Something that cannot go on until someone acts | A failure |
| `warning` | In doubt, or about to stop something; an `ErrorMessage` and a `Banner` use it | Information that needs no action (`info`) |
| `info` | A neutral note | A problem (`warning`) |
| `pending` | On its way: a check that is running | Waiting for a person (`waiting`) |
| `waiting` | Held up by someone: «Venter på review» | A check that is running (`pending`) |
| `view` | Someone is asked to look: a review | A search (`search`) |
| `question`, `discussion` | An unanswered question; a conversation | A comment on a pull request (`discussion` is the kind of thing, not an action) |
| `place` | A place on the map | The home page (`home`) |
| `link`, `external` | A link to a place in the app; a link out of the app (always with its words) | Each other |
| `time`, `history`, `calendar` | A duration or an age; what happened before (a log); a date | Each other |

## Sizes and tones

`size`: `sm` (14 px) in a line of small text (a `StatusLine`), `md` (16 px, the default) beside normal text, `lg` (20 px) where an icon stands
by itself (an empty state). `tone`: the text's own colour by default; `muted` for a quiet kind; `destructive` for what
stops something; `primary` for the one thing to look at.

## Accessibility

- An icon is **decorative by default** and hidden from a screen reader (`aria-hidden`): the words beside it say the same.
- Where an icon **stands alone and carries the meaning** (the kind of a row), give it a `label` (`iconLabel` on a row).
- An **icon-only button** needs an `aria-label`.
- A status must read the same **without colour**: that is why `StatusLine` pairs a symbol with its words.

## Icon and word

- The icon stands **before** the word, at the start of the line, centred on the line's height (not on its baseline), at the size of the text: `md` (16 px) beside 14–16 px text, `sm` (14 px) in small text (Carbon, Atlassian).
- The icon takes the text's colour (4.5:1 as text). An icon that stands alone and is needed to understand the page needs 3:1 against what is next to it (WCAG 1.4.11); one beside its word, or purely decorative, is exempt.
- An icon that is **a control** (alone) is at least 24 × 24 px with spacing (WCAG 2.5.8); in practice ours are words with an icon, so this is rare.

## Accessible names

| The icon is | Do |
| --- | --- |
| Beside its word | Nothing: it is decorative and hidden from a screen reader (the default) |
| The kind of a row, alone | `label` on the icon («Pull request»), so the kind is read before the name |
| A control with no word | A name that says **what it does**, not what it looks like («Kopier kommando», not «Ikon med to ark»), as `aria-label` on the control or hidden text; never `title` alone. When the word on screen changes, change the name too: the accessible name contains the visible one (Primer) |

Do not label the SVG itself for a control; label the control (Sara Soueidan: labelling the `svg` fails in some browser and screen reader pairs).

## State: filled and outline

Material Symbols has a `FILL` axis for a selected or active state, and the usual way is outline for the default and filled for selected. We do **not** use it yet: our states are told with words and the symbol of the state
(`StatusLine`, `Badge`). If a control needs a filled variant (a favourite that is on), add it as a separate meaning (`favorite-on`), with a real use, rather than a prop.

## Governance

- **The set is complete on purpose.** A page should never wait for an icon: the meanings a read-mostly dashboard asks for are all in the Catalogue. Look there first.
- **A meaning that is missing is added at once**, without waiting for a second use: in its group in `scripts/icon-set.mjs`, named for what it means, with one Lucide glyph, and `npm run icons` regenerates the shapes, the types and the Catalogue. One glyph for one meaning (a test fails otherwise).
- **Change a glyph** in `src/lib/icons.ts`: one line, and every page follows.
- **Remove or rename** by keeping the old name as an alias for one minor version, then removing it in a major (as for a component).
- **Brand marks** (GitHub, LinkedIn, Spotify) are marks, not meanings: they do not go in `ICONS`, are never recoloured and always have their name as text.
- Lucide's own conventions (24 px canvas, 2 px stroke, round caps) are why the set looks the same; do not mix in a glyph from another set.

## Keep it recognisable

- The same meaning has the same symbol on every page; never pick another glyph in a page.
- An icon in front of a word is read as part of the word: put it before the text, at the start of the line.
- Do not recolour an icon to mean something; a state is told with its symbol and words.
- Count them: a page where every line has an icon has none that stands out. Use them for kinds, states and actions.

## Adding a meaning

1. Look in the Catalogue: the meaning is probably there already. Use it.
2. If not, add it **now** to its group in `scripts/icon-set.mjs` (the meaning and a Lucide glyph) and run `npm run icons`. The shapes (`src/lib/icon-nodes.ts`), the `IconName` type and the Catalogue are generated.
3. Never import from `lucide-react` in a page: a test fails on it. Two meanings may not share a glyph: that test fails too.

## How an icon is drawn

An icon is an **inline `<svg>` that the server renders as plain HTML**: the shapes are data, there is no icon component and no script, and the look is CSS (`src/icon.css`): `--icon-size` for the size, `currentColor` for the colour (so it follows the text), `data-tone` for
another token, and `scale: -1 1` under `:dir(rtl)` for the meanings that point somewhere (back, next, sign in). In forced colours the stroke stays `currentColor`, which the browser maps to a system colour, so it never disappears. The `width` and `height` attributes are the
fallback until the stylesheet has arrived, so the page does not jump.
