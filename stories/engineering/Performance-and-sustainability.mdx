# Performance and sustainability

A light page is fast, cheap on a phone's battery and data plan, and emits less. The same choices serve all three, so this guide treats them
as one. Researched against web.dev (Core Web Vitals, images, fonts, long tasks), the HTTP Archive Web Almanac 2025, the **W3C Web
Sustainability Guidelines** (WSG, Group Note Draft 2026; criteria in brackets below), the Sustainable Web Design Model v4, GOV.UK's guidance
on sustainable services, Low-tech Magazine's solar site and W3C COGA.

## 1. What a page of this system costs

Measured on a built page of an app on the design system (`npx designsystem-budget dist`):

| Part | Sent | Note |
| --- | --- | --- |
| HTML | 2–3 KB | rendered on the server, gzip |
| CSS | about 15 KB | one stylesheet, only the classes used (Tailwind) |
| Script | 0 KB | a page with no island sends none |
| Fonts | about 70 KB | Geist and JetBrains Mono, variable, `latin` files only |
| **Total** | **about 85 KB** | about 0.013 g CO2e a view, rating A+ |

The pictures are the rest, and on a list of covers they are most of it: forty thumbnails of 20 KB are 800 KB. **The picture is the first
thing to look at.**

## 2. Core Web Vitals, and what the components do for each

Good is **LCP ≤ 2.5 s, INP ≤ 200 ms, CLS ≤ 0.1** at the 75th percentile of real visits.

- **LCP (largest paint):** the hero `Picture` of a detail page is `priority`: fetched at once and first (`loading="eager"`,
  `fetchpriority="high"`). Every other picture is lazy. Only one picture on a page is `priority`; a lazy LCP picture is the most common
  mistake on the web (one mobile page in six).
- **CLS (layout shift):** every box that waits has its size from the first paint: a `Picture` frame, a chart's reserved height (`ChartFrame`),
  `SectionSkeleton` at the height of what comes. Fonts swap in a family with metrics close to the fallback.
- **INP (response):** no component hydrates unless it reacts (`"use client"` only on leaves: `server-safe.test.ts`); charts are islands that
  load when visible (`client:visible`, `next/dynamic`). A handler that does much yields to the browser between steps.

## 3. Pictures [WSG 2.9, 4.3]

- **`sources`**: give `Picture` every width the source offers (TMDB `w92`, `w185`, `w342`; Last.fm `64s`, `174s`, `300x300`). It writes
  `srcset` and a `sizes` that is the width it is drawn at, so a 40 px thumbnail takes the 92 px file on a sharp screen, not the 300 px one.
- **`priority`** on the one picture that leads the page; lazy everywhere else.
- The frame keeps its ratio when the picture fails or is missing: a dead API never breaks the layout [WSG 3.10].
- A picture that only decorates is not added. No autoplay of video or sound [WSG 2.9, «User-controlled media»].

## 4. Fonts [WSG 2.11]

Two families, variable (one file for every weight), self-hosted (no third party sees the reader), `woff2`, and only the `latin` files are
fetched by a Norwegian page (`unicode-range`). `font-display: swap`: the text is there at once. A third family, or a second weight file, is
not added. An app may preload the one body font (Geist `latin`).

## 5. Script and CSS [WSG 3.2, 3.3, 3.7]

- No third-party script, font or CDN [WSG 3.5]: the theme, fonts and icons ship with the package; icons are inline SVG data.
- Heavy parts load when they are needed: charts when visible, overlays when opened.
- Motion is `transform` and `opacity` only, from the motion tokens, and none under `prefers-reduced-motion` [WSG 2.10].
- A long list renders what is on screen (`VirtualTbody`), not thousands of rows.

## 6. Budgets, in CI [WSG 3.1, 2.15]

`npx designsystem-budget <dist>` weighs every built page (HTML, linked CSS and script gzipped, the `latin` font files, the pictures from the
site's own folder) and **fails above the budget**:

| | Budget |
| --- | --- |
| Total | 500 KB |
| Script | 150 KB |
| CSS | 50 KB |
| Fonts | 100 KB |

Pictures from other hosts are counted, not weighed: keep them small with `sources`. Change a limit with `--total=…`, `--js=…` and so on,
in the app's CI, with the reason beside it.

## 7. Emissions per view: what the number means

The budget tool also gives **grams of CO2e per view** with the **Sustainable Web Design Model v4**: 0.30 kWh per GB sent (data centre,
network and device, in use and in their making), times the global grid of 494 g/kWh: about **0.15 g per MB**. The ratings: A+ ≤ 0.040 g,
A ≤ 0.079, B ≤ 0.145, C ≤ 0.209, D ≤ 0.278, E ≤ 0.359, F above.

It is an estimate that errs high on purpose, from bytes alone: good for «is this page light, and did my change make it heavier», not for
«what does this component emit». More than half of it is the reader's device, so green hosting helps less than a lighter page.

## 8. Data that updates [WSG 4.2, 4.7]

- Refresh as often as the data changes, not more: departures every minute, the weather every half hour, a media log every few hours.
- Hashed assets are cached for a year (`immutable`); data is revalidated (ETag, `stale-while-revalidate`).
- A page that refreshes stops while hidden (guide «Fresh data and offline»).

## 9. Myths

- **«Dark mode saves energy»**: only on OLED screens at high brightness (about 40 % of the display's power at 100 %, 3–9 % at the usual
  30–50 %), and nothing on LCD. The theme follows the device for comfort and choice; it is not a carbon measure and is never forced.
- **«Green hosting makes the site green»**: the device is the larger part.
- **`prefers-reduced-data`** is in no browser yet, and `Save-Data` only in Chromium: an app may use them as an extra, never rely on them.

## 10. Less is also easier [W3C COGA]

What makes a page light also makes it easier to use: less content, one task per page, no motion that is not asked for, no interruptions.
See the guides «Reading and hierarchy» and «States and messages».

## 11. Check

- [ ] `npx designsystem-budget dist` passes in the app's CI.
- [ ] One `priority` picture at most, on the picture that leads the page; every picture with `sources` where the source offers widths.
- [ ] No third-party script, font or CDN; no autoplay.
- [ ] Nothing hydrates that does not react; charts load when visible.
- [ ] Data refreshes no more often than it changes.
